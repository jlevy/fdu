Plus one committed fixture comparing fdu against the metabrowser walker's semantics (symlinks as leaves, hidden allowlist, gitignore negations), differences documented or eliminated. This is the acceptance test fdu-p02b asked for.

## Notes

FDU47-B2 FIXED, B3 and B4 corrected at ff210d0.

B2. The identity recipe now matches the consumer contract at 1e0f9b5: SHA-256 over a
compact JSON array of sorted `[name, value]` STRING pairs, and two digests rather than one.
`scope_fingerprint` carries the budgets, the visibility allowlist and the boundary policy;
`semantic_fingerprint` carries the type, tag and reducer registrations. A structured value
is a compact canonical JSON string inside the outer array, so the scope digest carries the
allowlist itself rather than fdu's `hidden_fingerprint` -- a digest of a list is not the
list, and no second implementation could reproduce it.

The scope digest is built from the `ScanOptions` the adapter opened with rather than from
`ScanScope`, because that is where the allowlist is. `hidden="keep"` has no counterpart on
the consuming side, whose model always prunes except an allowlist; a provider adapter
prunes.

The old test built the same wrong encoding by hand, which proved internal consistency and
nothing else. It now pins both digests separately and moves every component of each,
including the one that must NOT cross: folding `hidden_fingerprint` into the semantic
digest fails the test. Three mutations checked -- object encoding, hidden folded into
semantic, unsorted allowlist.

STILL OPEN, and this is what keeps the bead open: the component *set* is the part a second
implementation cannot infer. fdu has no `max_entries` budget where the consumer does, so
the two scope digests differ for the same tree until the shared conformance fixture pins
which components belong. That fixture is fdu-kl7r.

B3 and B4 are corrections to the example rather than closures of their gates.
`recent_page` paged root children -- `after` and `limit` went to `children_of`, an
unrelated projection, while the report was truncated independently and continued nowhere.
It is `recent_slice` now and says what it is. `invalidation()` no longer rebuilds paths
from `changes`; it reads the bounded fields the batch already carries. The underlying
gates stay with fdu-91ru and fdu-vfx7, and the example names them rather than working
around them.

EXACT-HEAD REVIEW at FDU d19b0ce / MetaBrowser 0577bb1 (2026-08-25). The ff210d0 digest helper still does not reproduce the implemented consumer scope digest. MetaBrowser hashes exactly hidden_allowlist, max_depth, and max_files with UTF-8 JSON (contract.py:101-122; architecture lines 60-81). browser_provider.scope_fingerprint additionally hashes follow_symlinks and stay_on_filesystem, renders absent numeric limits as null, and uses ensure_ascii=True (browser_provider.py:109-160). At the current MetaBrowser contract, symlink traversal and breadth-first order are fixed semantics, watch mode is observation policy, and filesystem confinement is not an InventoryConfig axis. Pin the exact component set and bytes against a shared fixture, including a non-ASCII hidden name, rather than another locally reconstructed expectation. This is a thin-adapter identity correction, not a compatibility layer.

EXACT-HEAD UPDATE at FDU d0a6a6a / MetaBrowser 0577bb1 (2026-08-25). Special-object inventory behavior is accepted and remains on closed fdu-bjhy, but the reference adapter expands the shared scope digest again: `browser_provider.scope_fingerprint()` adds `exclude_special`, while MetaBrowser hashes exactly `hidden_allowlist`, `max_depth`, and `max_files` with UTF-8 canonical JSON. Special exclusion is fixed provider semantics, not an InventoryConfig axis. Also derive the native value after parsing rather than from raw `ScanOptions.special`: native accepts trimmed/case-insensitive `prune`, while the helper currently treats any spelling other than exact lowercase as false.

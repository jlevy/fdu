  WHAT LANDED

  `crates/fdu-py/examples/browser_provider.py`: boot with the plane promoted and hidden
  paths pruned, serve dual-value listing rows from one call, translate a batch into the
  invalidation a view layer acts on, and page a recency slice against the caller's own
  instant. Exercised from `public_smoke.py` by loading the file that ships.

  `semantic_fingerprint`: named components, sorted by name, canonical JSON (ensure_ascii,
  compact separators, sorted keys), SHA-256 hex. Asserted against bytes built by hand in the
  test rather than against a second call to the function -- a test that compared the function
  to itself would accept any recipe, and a second implementation has to reproduce these
  bytes. Every named fingerprint goes in, and the test moves each one in turn: a recipe that
  dropped `hidden` would have passed three of the four.

  The filesystem scenarios the bead named: symlinks as leaves (a symlink to its own parent,
  which hangs if it is followed), the hidden allowlist, and a nested `!keep.log` beating a
  broader `*.log` above it -- decided by `.gitignore` files that pruning kept out of the
  index entirely, which is the part that would silently answer "nothing is ignored".

  Five mutations, each caught: dropping a component from the identity, dropping the plane
  from the listing, keeping hidden paths, enabling the wrong rule, and resolving the
  recency window's own instant instead of the caller's.

  A real gap left by fdu-xyvu turned up here: `hidden_fingerprint` reached `ScanScope` in
  the engine and never reached Python, so a consumer's cache key could not have seen it.
  Fixed in the same change.

  WHAT DID NOT, AND WHY (fdu-kl7r)

  The vendored conformance packet, the recorded-observation replay driven into both
  engines, and one combined identity agreed byte for byte. All three need the consuming
  repository in the loop; fdu now has the semantics, the recipe and its own answers over the
  shared scenarios committed, which is what the other side has to be diffed against.

  Landed in 4eac1b2 on claude/fdu-interactive-client-implementation-map (PR #47).

## Notes

FDU47-E4 addressed at 353d48f.

Three things in the reference adapter were stale or wrong:

- main() opened the default row-carrying interest and both the module docstring
  and invalidation() repeated caveats about invalidations-only delivery and
  terminal state being absent -- gaps that closed at 515d52c and eaae030. It now
  uses Interest.INVALIDATIONS and prints the terminal freshness and the batch's
  work, so the example shows zero entry rows crossing the binding.
- The opening prose said "identity is one string, and it must combine every
  fingerprint", while this consumer deliberately keys on a scope digest and a
  semantic digest separately because they invalidate different things. Rewritten
  to say which fact goes in which and why the split is the decision.
- The provider-allowlist fixture case claimed to be what _options() opens while
  carrying .cargo, which _options() does not allowlist. Relabelled: it is the
  two-name case the order-independence case reorders, and the provider's own
  scope is the separate this-repository-s-provider case added earlier.

Still open on this bead: the cross-engine half. The fixture is FDU's side, with
digests taken by executing the consumer's own function. Making it a fixture both
engines consume, and pinning the strict-cap boundary case and special-object
replacement against a recorded observation stream, is fdu-kl7r.

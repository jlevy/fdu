A runnable, CI-tested example under crates/fdu-py/examples: boot, serve dual-plane tallies, stream changes with dirty sets, resume from a cursor — the seam of the metabrowser adoption. Plus one committed fixture comparing fdu against the metabrowser walker's semantics (symlinks as leaves, hidden allowlist, gitignore negations), differences documented or eliminated. This is the acceptance test fdu-p02b asked for.

## Notes

FDU47-C3 addressed at ce8d78b: the reference embedder now produces the consumer's
scope-digest bytes rather than a second recipe.

Three differences, each invisible to a test that hashed with the same helper:

- Six components where the consumer's config has three. Two of the extras --
  symlink traversal and filesystem boundaries -- the consumer has no name for at
  all, and a third (exclude_special) had just been added. An adapter that invents
  a component produces an identity no second implementation can reproduce.
- ensure_ascii=True, so a valid non-ASCII allowlist name escapes to \\uXXXX and
  every digest differs.
- "null" for an absent bound, a value the consumer never emits, because its
  config has no way to spell an unbounded walk.

Now exactly hidden_allowlist, max_depth, max_files, compact UTF-8 JSON, bounds
required. The axes that dropped out are not a hole: two indexes differing in
symlink traversal or special-object admission really are different inventories,
so ignoring a *free* axis would let a consumer cache across a change that
invalidated it. Inside the provider view they are not free -- open_tree fixes
each and scope_fingerprint refuses options that disagree. Checked, not hashed,
because hashing an axis the consumer cannot name fails the same way one axis over.

crates/fdu-py/tests/fixtures/scope-fingerprint.json carries seven cases with
digests taken by *executing* the consumer's own function, not by re-reading its
spec -- a recipe re-typed from prose agrees with the prose, and the previous
version of this code was internally consistent and agreed with nothing. The
non-ASCII case is the only one that can catch ensure_ascii, and reverting that
one flag fails exactly it.

The example also now opens the bounded scope its digest describes -- it could not
until fdu-7sou landed, because a bounded index could not be watched and the
example follows the tree. One builder (_options) serves the open and the digest,
and the fixture pins that exact scope so the two cannot drift.

Still open on this bead: the cross-engine agreement half. The fixture is FDU's
side; making it a fixture *both* engines consume, and pinning the strict-cap
boundary case and the special-object boot/live-replacement scenarios against a
recorded observation stream, is fdu-kl7r and needs the consuming repository.

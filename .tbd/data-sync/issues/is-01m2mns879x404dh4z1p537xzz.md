Found by the 2026-09-16 local release rehearsal of the 0.1.0 candidate at origin/main 16efcd0.

Every `cargo package` and `cargo publish` of fdu-core prints:

    warning: ignoring example `perf_probe` as `examples/perf_probe.rs` is not included in the published package

Cause: crates/fdu-core/Cargo.toml:14 sets include = ["src/**", "tests/**", "rules/**", "build.rs", "Cargo.toml", "README.md", "LICENSE"], which omits examples/**, while crates/fdu-core/examples/perf_probe.rs exists and auto-discovery still finds it. Cargo resolves this correctly — the normalized manifest inside fdu-core-0.1.0.crate already carries autoexamples = false, and the packaged file set is right (61 files, 586.7 KiB compressed) — so this is warning noise, not a defect in what ships.

NOT a 0.1.0 blocker. Recorded because the warning appears in the `cargo publish` output at the least recoverable moment of the release, where an unexplained warning invites a pause.

Fix when convenient: add `autoexamples = false` to [package] in crates/fdu-core/Cargo.toml, which states the intent cargo already infers. Deliberately not fixed during the rehearsal: changing a published manifest for a cosmetic warning is an unforced change immediately before a first publish.

A caller-tree profile of a `--cache only` warm content open (exp-104, cargo-registry
subject, 3,077 entries) attributes 19.43% of the profile and 25.5% of the engine to
`Index::install_controls` -> `reclassify_controlled_subtrees`, almost all of it
`ControlMatcher::is_ignored` -> `std::path::compare_components`: 10.87% of the profile
from 47,690 calls. After the two loaders it is the largest single engine item on this
tier.

This is not redundant work. `install_controls` already short-circuits when neither the
incoming nor the held control table governs anything, so the walk only runs on trees
that actually carry gitignore state -- which the cargo registry subject does, and which
most real checkouts do.

What makes it a target is the mechanism: it is `Path` component-by-component comparison,
the exact cost exp-069/H102 removed from `ContentIndex::files` by ordering that map on
the path's bytes instead (-31.00% on the warm content job). The same shape appears here
in a different map, and no one has measured whether the same answer applies.

Cautions for whoever picks this up:

- It is correctness-sensitive in a way the content maps were not. Gitignore precedence
  is ordered and negation-bearing, so any reordering has to preserve match semantics
  exactly, not just membership. Gate it with the existing control goldens plus an
  assert-same-image differential run before trusting any timing.
- Size it on the decisive subject first. exp-104 is a worked example of this same tier
  overstating a saving about 2x between a 3k-entry screening subject and a 102k-entry
  deciding one, and the 19.43% above is a screening-subject number.
- Screen it against exp-104's other result: the warm content open is no longer
  instruction-bound, so a change whose only mechanism is "fewer comparisons" may measure
  zero on wall exactly as H103 did. What made H102 work was that it also changed the
  memory access pattern (one memcmp over contiguous bytes instead of a pointer-chasing
  component walk). Prefer a form that does the same.

Overlaps fdu-refc (S6, per-directory extension tallies) and the control-state scale
epic fdu-2lkf; check both before starting so two hypotheses do not compete for one cost,
the way H13/H18 and fdu-91ts/H74 did.

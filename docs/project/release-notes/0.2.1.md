fdu 0.2.1 is a patch release focused on Linux.
The default `fdu PATH` and `--view summary` are about three times faster on source trees
with many `.gitignore` files, the default summary no longer builds a full index to
report its ignored share, and building the full index is faster on trees of many small
directories.
A `.gitignore` spelled in another case now applies where git applies it, and
an answer served from the cache with `--stale-ok` always says it is stale.
There are no incompatible changes to the command line, the report schemas, or the Rust
and Python APIs.

## Performance

Three engine changes were each measured on their own, on a quiet 4-vCPU virtualized ext4
host with warm caches:

- **Ignore rules without allocation, resolved once per directory.** On the Linux v6.12
  source tree (92,474 entries, 358 `.gitignore` files) the default tree fell from 590 to
  211 ms and the default summary from 505 to 167 ms, with identical answers
  ([exp-173](https://github.com/jlevy/fdu/blob/v0.2.1/docs/project/experiments/exp-173-linux-h162-allocation-free-gitignore-matching-halves-the-def.md),
  [exp-174](https://github.com/jlevy/fdu/blob/v0.2.1/docs/project/experiments/exp-174-linux-h163-per-listing-control-chains-cut-another-third-from.md)).
- **A summary that reads ignore rules without an index.** On a million-entry tree with
  no `.gitignore` the default summary took 19% less time and its peak memory fell from
  314 to 8.6 MiB; on the source tree, 7% less time and 23% less memory
  ([exp-187](https://github.com/jlevy/fdu/blob/v0.2.1/docs/project/experiments/exp-187-linux-h161-ignore-aware-transient-summary-clears-wall-rss-ba.md)).
  On macOS its peak memory fell 58–69%.
- **Directory listings freed where they were allocated.** Building the full index took
  8.6% less time on a `node_modules` tree and 10.6% less on the generated million-entry
  tree, whose directories are small; trees with few, larger directories are unchanged
  ([exp-190](https://github.com/jlevy/fdu/blob/v0.2.1/docs/project/experiments/exp-190-linux-h159-listing-recycle-clears-3-percent-on-a-real-direct.md)).

Against its peers on the generated million-entry Linux tree, a screen of the release
candidate built the reusable index and a ten-row tree 6% slower than pdu rendering the
same depth (95% interval 1% to 10%), level with diskus returning one number, and faster
than dust (+50%), GNU `du` (+125%), and dua (+185%); in 0.2.0 the gap to pdu was 21%.
The
[pdu brief](https://github.com/jlevy/fdu/blob/v0.2.1/docs/project/research/research-2026-09-28-pdu-and-the-linux-peer-gap.md)
explains where the remaining Linux gaps come from and what comes next.
On macOS, where fdu was already the fastest tool measured, these changes were not
re-measured for this release.

## Highlights

- **Case-variant `.gitignore`.** On a case-insensitive volume (APFS and NTFS by default,
  an ext4 casefold directory), a `.gitignore` spelled `.GITIGNORE` or in any other case
  now governs, as it does for git; on a case-sensitive volume it stays an ordinary file.
  Every route agrees, and the rules are reported under `.gitignore`.
- **Stale answers say so.** A `--stale-ok` answer prints
  `warn: stale answer: served from the snapshot without filesystem verification` on
  stderr on every format, and `--quiet` keeps it.
  Python reports carry it in the new `Report.warnings`.

## Install

```shell
uvx --no-build fdu@latest --help    # run the latest release without installing it
uv tool install --no-build fdu      # the command line from a prebuilt wheel
cargo install --locked fdu          # the command line, built with Rust 1.85 or newer
pip install fdu                     # the Python package: import fdu
```

Re-run `uvx --no-build fdu@latest --install-skill` after upgrading so the agent skill
describes this release.

## Compatibility

This is a patch release: no command-line option, report or cache schema, or Rust or
Python API changed incompatibly, and `cargo-semver-checks` finds no breaking change in
`fdu-core` or `fdu` against 0.2.0. Two additions: Python `Report.warnings` and Rust
`report_format::report_warnings`.

## Upgrading from 0.2.0

- **First run scans cold.** The engine fingerprint changed with the `.gitignore` rule,
  so 0.2.1 reuses no snapshot or content sidecar written by 0.2.0: each cached tree’s
  first run walks it, and its first analyzed run reads every file again.
- **Stderr.** A script that expects empty stderr from a `--stale-ok` run now sees one
  `warn:` line; paths and long output no longer print `note: cache-only result`.

## Known Limitations

- **Linux.** On source trees with many `.gitignore` files the default command still
  takes about three times pdu’s time, because classification runs on one thread;
  building the full index on the generated tree still trails pdu by about 6%.
- **Memory on Linux source trees.** The ignore-aware summary holds about 20 MiB more
  than a walk without `.gitignore` on the Linux v6.12 tree, which is not yet explained.
- The 0.2.0 limitations on links, cache retention, watch backends, opened roots, and
  JSON integers still apply.

## Security

Publishing now refuses a release tag that is not annotated, verified by GitHub, and on
`main`, checks the Rust API with `cargo-semver-checks` before uploading, and publishes
to crates.io only through trusted publishing.
Report vulnerabilities through GitHub’s private vulnerability reporting, as
[SECURITY.md](https://github.com/jlevy/fdu/blob/v0.2.1/SECURITY.md) describes.

## What was predicted

H160: under `--cache auto` a one-shot metadata report never reads the snapshot (H108),
and no later one-shot report reads what it writes, yet every such run encoded,
checksummed, wrote, and synced a full image: 0.26 s of a 1.51 s default `fdu .` on a
million-entry Linux tree, per the
[cache economics brief](../research/research-2026-09-27-cache-economics-and-default-plans.md).
Letting `auto` decide per analysis, and skip persistence for one-shot metadata reports,
removes that work without changing any answer.

Named before recording: `default-tree` wall down at least 3% with the interval below
zero; `cold-scan-index`, which writes nothing on either arm, is the placebo and must
include zero.

## What was measured

Quiet 12-pair probe run on the generated `balanced` 1,000,001-entry tree, control built
from the branch the change is stacked on and candidate from the change itself.

- `default-tree`: −13.81% [−15.99%, −10.65%]. Accept.
  The snapshot is prepared by `cold-open-save`, so the control arm re-encodes and
  compares an existing image while the candidate leaves it alone.
- `default-tree-first`: −32.74% [−33.57%, −24.41%]. The control writes a first image,
  including its `fsync`; the candidate writes nothing.
- `cold-scan-index` (placebo): −1.32% [−3.54%, +1.25%].

A CLI screen on the same tree, 10 runs each, agrees: `fdu .` 1.51 s before and 1.25 s
after, against 1.29 s for `--cache off`; the default summary 1.51 s and 1.26 s;
`--cache on` 1.51 s, the old default’s cost; and a `--stale-ok` read of that snapshot
0.90 s.

## Decision

Accepted and shipped as a policy change rather than a tuning: `--cache` takes `auto`,
`on`, or `off`, `auto` persists only where a later request reads what it stores (content
analysis, sessions, watches, refreshes), and `--cache on` restores the old write for
callers who want a snapshot, for example to seed `--stale-ok`, which replaces
`--cache only`. The change is not platform-gated and is unmeasured on macOS.

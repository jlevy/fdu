# Feature: CLI UX and Zero-Install Agent Skill

**Date:** 2026-08-09

**Author:** fdu project

**Status:** Follow-up PR #2 open; local handoff gate complete and CI in progress

## Overview

Make the native `fdu` command a coherent interface for humans, shell pipelines, coding
agents, and Python package users.
One Rust implementation owns argument parsing, rendering, diagnostics, and exit status.
The PyPI wheel exposes that implementation as the `fdu` console entry point so a
published release can run through `uvx` without a separate install or a second CLI
implementation.

The current CLI already has versioned JSON, bounded default output, deterministic
sorting, explicit partial-result status, TTY color suppression, `NO_COLOR`, and quiet
broken-pipe handling.
This plan closes the remaining pre-release gaps: color control is not forceable, human
warnings share stdout with primary data, ANSI sequences are hand-written, help omits
important operating rules and examples, deep rendering is recursive, the Python wheel
has no command entry point, and no portable skill describes safe agent use.

## Goals

- Give terminal users restrained semantic color, concise aligned output, readable help,
  correct singular/plural labels, and actionable diagnostics
- Keep redirected output ANSI-free by default and support one explicit
  `--color=auto|always|never` contract with `NO_COLOR` and `FORCE_COLOR`
- Keep stdout as the primary-result stream and stderr as the diagnostic stream
- Keep agents on stable, schema-versioned JSON with documented completeness, truncation,
  scope, cache side effects, and exit semantics
- Make every retained tree depth renderable without consuming the process call stack
- Expose the same Rust CLI from the installed `fdu` wheel so `uvx fdu` works after the
  package is published
- Provide one concise, self-contained Agent Skills document through `fdu --skill`, with
  local-first execution and an exact-version `uvx` fallback
- Prove native-binary and installed-wheel behavior end to end on supported CI platforms

## Non-Goals

- Publish to PyPI or crates.io in this pull request; name availability, performance
  evidence, release workflows, and trusted publishing remain under `fdu-9cf0`
- Claim that `uvx fdu` works from the public registry before a release exists
- Add a skill installer, managed `AGENTS.md` block, hooks, plugin framework, or other L2
  or L3 agent-platform machinery
- Add prompts, paging, progress animation, configuration files, or destructive commands
- Implement the later JSONL, metric sorting, gitignore tagging, or adaptive terminal
  layout work already owned by `fdu-jej9` and `fdu-oqoy`
- Duplicate the Rust CLI in Python or add a third workspace crate

| --- | --- | --- |

| Agent data | `fdu.tree/2`, complete/truncated/scope fields, raw path identity | Portable skill and exact color/stream behavior; schema remains unchanged |

## Compatibility

- **Command line:** This is an unpublished pre-release interface.
  Replace `--no-color` with `--color <auto|always|never>` rather than retaining two
  overlapping controls.
  Existing behavior remains `auto`, and `NO_COLOR` remains supported.
- **Rust library API:** Preserve the non-CLI API. The feature-gated CLI process helper
  may change because its only consumers are this workspace’s native and Python entry
  points.
- **Python API:** Preserve `fdu_py.open`, `scan`, and `Index`. Add `fdu_py.main` only as
  the console-script target.
- **JSON and snapshots:** Preserve `fdu.tree/2` byte shape and snapshot format v2. A
  schema version change is not authorized by this plan.
- **Published artifacts:** N/A until `fdu-9cf0` completes.
  The first publication must verify the package name and the skill’s exact fallback pin
  before claiming registry execution.

## Design

### One Process Boundary

Move parsing, help/version rendering, stream selection, execution, error-chain
formatting, broken-pipe handling, and numeric exit selection into the feature-gated Rust
CLI module. `main.rs` delegates to it.
The PyO3 console function extracts Python’s `sys.argv` as native `OsString` values,
releases the GIL, and delegates to the same boundary.
PyO3’s native conversion preserves surrogateescaped Unix bytes and Windows wide-string
identity rather than narrowing the wheel’s CLI to UTF-8.

This follows maturin’s guidance for a package that has both a binary interface and a
PyO3 library: a Python console entry point calls an exported Rust CLI function instead
of shipping a duplicate binary in the wheel.
The command therefore cannot drift from the Cargo-installed executable.

### Color and Styles

Use clap’s re-exported `anstyle` types for both help and data.
Do not assemble escape codes manually.
The semantic palette is deliberately small:

- bold cyan for the scanned root and help headings
- cyan for directories and type labels
- green for proportion bars
- yellow for warnings
- red for fatal errors
- dim text for causal detail

Color never carries information by itself.
Slashes, words, indentation, and stream placement retain the same meaning without it.

The precedence contract is:

1. `--color=always` or `--color=never`
2. non-empty `NO_COLOR`
3. non-empty, non-zero `FORCE_COLOR`
4. terminal detection for the destination stream

`--color=auto` selects steps 2 through 4. JSON and skill output never contain ANSI,
including with `--color=always`.

### Human and Diagnostic Output

Primary tree/type results stay on buffered stdout.
Partial-read warnings and fatal errors go to stderr.
A partial scan still prints the useful result first and exits 2 unless `--allow-partial`
is present. Errors preserve the complete cause chain and broken pipes remain quiet
success.

Help is the complete invocation contract.
It includes representative human and JSON commands, allocated-versus-apparent size
semantics, render-versus-scan scope, cache behavior, stream separation, color
environment variables, absence of prompts/pagers, and exit statuses.

### Agent Contract and Skill

`--json` remains the automation surface.
The skill requires consumers to inspect all of these rather than treating parse success
as complete data:

- process exit status
- `schema`
- `complete` and `errors`
- `tree_truncated`
- `scan_max_depth`
- `freshness`

`fdu --skill` prints one complete `SKILL.md` with no relative resources.
The document tries `fdu` on `PATH` first, then shows
`uvx --from fdu==<exact-version> fdu` for a reviewed published release.
It never recommends an unversioned runner or `latest`. Because no fdu release exists
yet, project documentation must keep the fallback conditional until the first release
gate verifies that exact version on PyPI.

### Python and `uvx`

Add `[project.scripts] fdu = "fdu_py:main"` to the existing abi3 wheel.
The console function uses Python’s `sys.argv`, not the host process argument vector,
because a generated console wrapper adds the Python interpreter and wrapper path at the
process level. The installed-wheel smoke test proves:

- the existing `fdu_py` module contract
- `fdu --version` and complete `fdu --help`
- a real JSON scan through the console script
- a non-Unicode Unix path through the installed console script without identity loss
- usage failure exits 2 without a Python traceback
- the wheel remains independent of the optional watch feature

The first release later adds the public-registry check
`uvx --from fdu==<version> fdu --version`. Until then, an installed local wheel is the
equivalent end-to-end artifact boundary.

### Stack-Safe Rendering

Replace recursive human rendering, JSON truncation detection, and JSON serialization
with explicit frames.
Preserve byte-for-byte uncolored human and `fdu.tree/2` output.
A child-process regression renders a synthetic deep index on a deliberately small thread
stack so a recursive regression fails the child rather than aborting the main test
runner.

## Testing Strategy

Use the existing four tryscript sessions as the behavioral specification and add only
tests that expose a new contract:

- exact help, skill, human tree, type view, JSON, usage, and fatal-error transcripts
- focused Rust tests for `auto`, `always`, `never`, `NO_COLOR`, `FORCE_COLOR`, JSON
  suppression, semantic style reset, and output/cause formatting
- a Unix partial-result process test proving primary JSON and exit status; a renderer
  test proving human warnings use stderr
- a deep synthetic-tree child process with a small stack
- an installed-wheel smoke that imports `fdu_py` and invokes the generated `fdu` command
  for success, JSON, help, and usage failure
- a direct `uvx --from <local-wheel> fdu --version` smoke before publication
- the existing Linux, macOS, and Windows native golden matrix and the supported Python
  wheel matrix
- the complete `make check` handoff gate and watched PR checks

Tests compare stable text exactly.
ANSI checks assert semantic presence or absence at the byte boundary rather than
embedding invisible control bytes in Markdown goldens.
